# PaceOn

_(antigo Minhas Corridas)_

App pessoal (PWA) para organizar provas de corrida de rua: calendário, inscrições, kit, custos (estimado x pago), checklist, anexos e fotos, resultados, histórico e objetivos pessoais.

## Rodar localmente
```bash
npm install
npm run dev        # http://localhost:5173
npm test           # testes das regras e do motor de sincronização
```

## Publicar no Vercel
1. Suba esta pasta para um repositório no GitHub.
2. No Vercel: **Add New → Project → Import** o repositório.
3. Framework: **Vite** (detectado sozinho). Build `npm run build`, saída `dist`.
4. Deploy. O `vercel.json` já cuida das rotas internas (abrir `/corridas/...` direto funciona).

Não há variáveis de ambiente obrigatórias. As notificações push precisam de algumas (ver “Agenda por assinatura e notificações”).

## Onde ficam os dados
- Corridas, resultados, custos, checklists e objetivos: `localStorage` (chave `minhas-corridas:v1`, formato versão 2).
- Anexos e fotos: IndexedDB (`minhas-corridas-arquivos`).

Sem conta e sem sincronização entre aparelhos. **Ajustes** (engrenagem no Início) → **Baixar backup** gera um `.json`; marque “Incluir anexos e fotos” para levar os arquivos junto. **Restaurar** aceita backups da fase 1 e da fase 2.

## Teste ponta a ponta
```bash
npm run build && npx vite preview --port 4173 &
node scripts/e2e.mjs   # precisa do Google Chrome em /usr/bin/google-chrome
```

## Estrutura
- `src/lib` — regras puras: datas locais, tempos/pace, validação, estatísticas, .ics
- `src/services` — persistência (store) e backup
- `src/components` — UI compartilhada (navegação, cards, diálogos)
- Telas menos usadas (cadastro, resultado, ajustes, conta, compartilhar, comparar…) e a biblioteca do Supabase carregam sob demanda, para o app abrir mais rápido.
- `src/pages` — Início, Corridas (lista/mês/filtros), Cadastro, Detalhe, Resultado, Histórico, Ajustes

## Conta e sincronização (fase 3, opcional)
Sem configuração, o app funciona só no aparelho. Testes das telas de conta com o Supabase simulado: `node scripts/e2e-conta.mjs`. Para login e sincronização entre aparelhos:

1. Crie um projeto no [Supabase](https://supabase.com).
2. **SQL Editor → New query**: cole e rode `supabase/schema.sql` (tabela `records` com RLS por usuário e bucket privado `anexos`).
3. **Authentication → URL Configuration**: em *Site URL* coloque o endereço do app no Vercel (ex.: `https://minhas-corridas.vercel.app`) e adicione o mesmo em *Redirect URLs*. É para onde vão os links de confirmação de e-mail e de nova senha.
4. **Vercel → Settings → Environment Variables**: `VITE_SUPABASE_URL` e `VITE_SUPABASE_ANON_KEY` (Supabase → Settings → API, chave *anon/public*). Depois, faça um novo deploy.

Como funciona:
- Login com e-mail e senha. Cada usuário só acessa as próprias linhas (RLS) e a própria pasta de anexos.
- O aparelho continua sendo a fonte da tela e funciona offline; alterações ficam pendentes e sobem quando houver conexão (ao abrir o app, ao voltar a internet, a cada minuto e logo após cada alteração).
- Conflitos: vale a alteração mais recente (o banco recusa gravações mais antigas).
- Primeiro login num aparelho com dados: o app pergunta se envia esses dados para a conta.
- Sair da conta apaga os dados deste aparelho; eles continuam na conta.
- **Excluir minha conta** (Conta → Zona de cuidado, digitando EXCLUIR): confere a função `delete_my_account` no banco, apaga os anexos do bucket, os registros e o usuário. Precisa do trecho 5 do `schema.sql`.
- **Entrar com Google**: o botão só aparece quando o provedor Google está ativo no Supabase (Authentication → Sign In / Providers → Google, com Client ID e Secret do Google Cloud).

## Recursos extras
- **Avisos dos próximos 7 dias** no Início (fim da inscrição, mudança de lote, retirada do kit, dia da prova).
- **Agenda (.ics)** com lembrete na véspera e eventos separados para retirada do kit e fim da inscrição.
- **Aviso de nova versão** com botão "Atualizar".
- **Repetir prova** no ano seguinte (copia o evento, sem data, valores ou resultado).
- **Preencher pelo link da inscrição**: a função `api/preview.js` (Vercel) lê só a página indicada e devolve campos sugeridos (prioriza dados estruturados schema.org; senão, título e texto). Bloqueia endereços internos, limita tempo e tamanho e nunca devolve o HTML. Só funciona no app publicado. Se a página não trouxer os dados (sites montados no navegador), usa o próprio link: nome a partir do endereço e cidade/UF pela lista de municípios do IBGE (`src/data/municipios.json`, extraída do pacote npm `municipios-brasil`, licença MIT).
- **Arquivo do relógio** no resultado: .FIT, .ZIP do Garmin ("Exportar original"), .TCX ou .GPX. Distância e tempo do relógio, FC, subida e parciais por km. Guarda só o resumo. O leitor de FIT (`src/lib/fit.js`) é próprio, escrito a partir da especificação do protocolo; o SDK oficial do Garmin (`@garmin/fitsdk`) é usado só nos testes, para gerar arquivos de verdade, e não vai para o app publicado.
- **Análise da prova**: meta x resultado, ritmo pelas parciais (saída forte, quebra, split negativo), esforço, distância do relógio e comparação com provas anteriores.
- **Plano de prova / do objetivo**: pace e passagens para a meta, quanto falta para o objetivo de tempo, degrau intermediário e próximas provas candidatas. É plano de ritmo, não de treino.
- **Evolução**: este ano x anterior (até a mesma data), provas por mês e pace por distância.
- **Card para compartilhar** (Resultado → Compartilhar): imagem PNG gerada no aparelho, nos formatos feed (4:5), stories (9:16) e quadrado. Distância, tempo, pace, classificação, selos (recorde pessoal, primeira na distância, meta batida) e as parciais por km; fundo na cor do app ou com uma foto da prova. Usa o compartilhamento do celular; onde não há, baixa a imagem.
- **Comparar provas km a km** (Histórico → Comparar, ou no resultado): tempo, pace, FC, subida e esforço lado a lado; diferença por km e acumulada, maior ganho e perda, e em qual metade veio a diferença. Precisa das parciais do arquivo do relógio; sem elas, compara só os totais.
- **Retrospectiva do ano** (`/retrospectiva/:ano`, em Histórico → Evolução e no Início em dezembro/janeiro): provas, km, tempo correndo, recordes (contra o melhor de antes do ano), primeiras vezes, mês a mês, distâncias, lugares, metas, objetivos, gastos e km dirigidos (da logística), com card para compartilhar (sem gastos nem endereços).
- **“Como foi?”**: notificação no dia seguinte à prova inscrita sem resultado, abrindo o registro (desligável em Agenda e avisos).
- **Atalhos no ícone** (segurar o ícone do app instalado): Nova corrida, Registrar resultado e Próxima prova (`/proxima`).
- **Logística da prova** (`/corridas/:id/logistica`, pelo detalhe da prova): veja a seção “Logística, rotas e agenda do dia”.
- **Treinos** (`/treinos`, pelo atalho Treinos no Início): treinos estruturados que **você** (ou seu treinador) monta: aquecimento, corrida, tiro, recuperação, descanso e desaquecimento, por tempo, distância ou até o botão de volta, com alvo de pace ou de FC e blocos de repetição. Estruturas de exemplo só como ponto de partida (o app não prescreve treino). Resumo e estimativa de tempo/distância, “Treino de hoje” no Início, duplicar, status planejado/feito/não fiz. **Baixar para o relógio (.FIT)**: arquivo de treino gerado no aparelho por um codificador próprio (`workoutToFit` em `src/lib/workout.js`), conferido nos testes com o leitor oficial da Garmin; vai para `GARMIN/NewFiles` pelo cabo. **Planejado × executado**: importe o .FIT/.ZIP/.TCX da atividade; cada passo é comparado com a volta correspondente (pace dentro ou fora da faixa). Sincroniza como registro `workout` (trecho 11 do SQL; até lá, os treinos ficam no aparelho e a Conta avisa) e entra no backup.
- **Localização confiável na logística:** cada endereço guarda a precisão (número confirmado, só a rua, região do CEP, cidade). A coordenada do CEP só vale como exata quando um serviço de mapas acha o mesmo número na mesma rua e cidade; senão aparece como aproximada (≈). Endereços diferentes no mesmo ponto do mapa (o que gerava trechos de 0 km) são apontados antes de calcular, e “Localizar de novo” corrige os pontos e os favoritos. Aceita coordenadas coladas do mapa (ex.: `-23.0451, -46.9773`) para o ponto exato, como o acesso de um estacionamento. A rota é recalculada sozinha quando endereços, paradas ou a ordem mudam (só a permanência muda os totais sem consultar o serviço); respostas atrasadas são descartadas. Totais somados a partir de metros e segundos, conferidos com o total do serviço; tempo de paradas somado à parte.
- **Planejador de deslocamento (Logística):** paradas com lápis para editar (nome, rua, número, complemento, bairro, cidade, CEP, referência, permanência, coordenadas e status), mantendo o id e a posição; mudar só nome ou permanência não consulta o serviço. Ponto exato marcando no mapa (arrastar) ou digitando as coordenadas: vira “marcado por você”, sem fingir que o endereço foi achado com número. Trechos com os nomes, compactos, que se abrem com o caminho, as principais vias, o status das pontas, “Ver no mapa” e “Alterar caminho”: mais rápida, menor distância, evitar rodovias, evitar pedágios e as alternativas do OpenRouteService, com km, tempo, vias e diferença para a atual, desenhadas no mapa; ou personalizada por pontos de passagem tocados no mapa (não são paradas, sem permanência). A escolha fica salva por par de pontos e vale enquanto o par existir. Arrastar para reordenar (e ↑ ↓). Horários do trajeto: sair de casa, chegar e sair de cada parada, chegar ao destino (saída = chegada desejada − direção − paradas − margem; sem trânsito no ORS). Os trechos são arredondados para somar o total (calculado a partir de metros e segundos). Busca de endereço: a mesma rua em bairros diferentes é decidida pelo bairro do CEP, e uma letra de diferença na grafia do mapa (ex.: “Contrim”) não impede achar a rua. Favoritos com endereço editável; ao mudar, pergunta antes de atualizar as provas futuras que usam o endereço antigo.
- **Dia da prova, passo a passo** (modo Dia da prova, no dia): o passo atual do trajeto (sair de casa, chegar e sair de cada parada, chegar ao local) com botão para marcar o horário real; mostra “No horário / Atrasada / Adiantada” e projeta os próximos horários (se a hora de sair passou sem marcar, o atraso cresce com o relógio). Navegação no Google Maps ou Waze só até o próximo ponto, a partir de onde você está; “Avisar Dani: chego às …” no WhatsApp com o horário atualizado; desfazer a última marcação. Marcações ficam na prova (`dayLog`, sincroniza). Lembretes 5 min antes de cada saída com a tela aberta; com o app fechado, quem avisa é a agenda .ics baixada, que agora tem a saída de cada parada com alarme 10 min antes (os nomes das paradas não vão para a agenda por assinatura). Push no horário exato com o app fechado não é possível com o cron diário do plano gratuito do Vercel.
- **Volta passo a passo:** no dia da prova, depois da largada (ou ao marcar a chegada ao local), o painel passa para a volta: sair do local → chegar e sair de cada parada (“Buscar Dani” vira “Deixar Dani”) → chegar em casa, com marcações, atraso, navegação até o próximo ponto e lembretes, como na ida (sem WhatsApp: a pessoa está no carro). Os horários partem de “Sair do local às” (Logística → Volta); sem esse horário, estima largada + 2h30 e avisa. Botões Ida/Volta para alternar. Na aba Volta da Logística, os mesmos horários para conferir antes do dia.
- **Clima na largada** (detalhe da prova e Dia da prova, quando a prova está a até 15 dias): previsão do Open-Meteo (gratuito, sem chave) para o local da Logística ou a cidade da prova (a cidade certa pela UF), na hora da largada e no fim previsto (pela meta ou 6:30/km): temperatura, sensação, chuva, vento, umidade e dicas de roupa, hidratação e ritmo. Guardada no aparelho por 1 h; sem conexão, mostra a última com o horário.
- **Como foi a logística** (detalhe da prova, depois do dia): compara o planejado com as marcações do Dia da prova — saída de casa, cada trecho dirigido, cada parada, chegada (dentro ou além da margem) e a volta — e sugere ajustes para as próximas provas (preparativos finais, acréscimo por trânsito, tempo de parada de um lugar salvo, margem), aplicados no perfil com um toque; a prova que passou não muda.
- **Importar treinos** (`/treinos/importar`): por link (o pacote vai no fragmento `#p=…`, que não chega ao servidor) ou por arquivo .json. Mostra a lista com datas e resumo e adiciona como planejados, sem apagar nada e sem repetir os que já existem (mesmo nome e data).
- **Montar no Garmin Connect (só pelo celular):** em cada treino, os passos no formato do editor do Garmin Connect (tipo, duração, meta, blocos de repetição), para criar o treino lá e enviar ao relógio por Bluetooth enquanto o envio direto (Training API) não é liberado.
- **Semana de treinos** (topo de Treinos e resumo na Início): segunda a domingo, cada dia com o treino e a situação (✓ feito, ● hoje, ○ planejado, ! passou sem marcar, – não fez), totais da semana (feitos/planejados, tempo feito/planejado pelo relógio ou estimado, km do relógio), barra de progresso, navegação entre semanas e sequência de semanas cumpridas (todos os treinos com data feitos).
- **Mandar para o relógio sem cabo** (em cada treino): “Copiar para o Intervals.icu” gera o texto do construtor de treinos (seções Aquecimento/Principal/Série Nx/Desaquecimento, distância em km, pace como faixa `m:ss-m:ss/km Pace`, FC como texto) — com a Garmin conectada lá e “Upload planned workouts” ligado, vai para o Garmin Connect e o relógio. “Copiar prompt para o Claude (Garmin Connect)” gera instruções para o Claude com acesso ao navegador criar o treino no Garmin Connect, agendar e enviar ao relógio, sem mexer em outros treinos; na lista de Treinos, o mesmo prompt com todos os próximos treinos.
- **Kit retirado no dia da prova** (cadastro → Kit e retirada): a data passa a ser a da prova; o horário vem sugerido 1 h antes da largada (atalhos 45 e 30 min); local = a largada, se não houver outro. A agenda do dia faz chegar até esse horário (“Retirar o kit” na linha do tempo, com aviso se cair depois do aquecimento), a aba Kit da Logística dispensa o trajeto separado e, no Dia da prova, o passo “Retirei o kit” também marca “Kit retirado” no checklist.
- **Objetivo ligado ao plano de treino:** cada treino pode pertencer a um objetivo (campo “Objetivo” no treino, “Escolher treinos do plano” no objetivo, ou o atalho “Criar objetivo com estes treinos” em Treinos, que já preenche a distância do teste e o prazo do último treino e liga os planejados). O objetivo mostra o plano (feitos/total, semana N de M, próximo treino) e, nos objetivos de tempo, o teste do plano com o arquivo do relógio na distância do objetivo conta como marca (“Melhor: 38:40 (teste em treino)”); prova oficial mais rápida continua valendo.
- **Importar atividade do relógio em Treinos:** um ou vários arquivos (.FIT, .ZIP, .TCX, .GPX); cada um vai sozinho para o treino planejado do dia (se houver um só) e o marca como feito; senão, a pessoa escolhe entre os treinos sem resultado até 3 dias de diferença ou registra um treino avulso. Arquivo já importado não duplica.
- **Carga da semana:** tempo da semana (planejado ou feito) × semana passada e média de 4 semanas, com aviso quando passa de 10% (e pelo menos 5 min) acima da semana passada.
- **Próximo bloco** (no objetivo de 5 km, com o teste feito ou na última semana do plano): a partir da marca nos 5 km, 4 semanas novas nos mesmos dias da semana, faixas de pace recalculadas (leve ritmo+55–95 s/km, ritmo +5–25, forte −30–0), volume 25 → 30 → 35 → 25 min e teste no fim, com objetivo novo (~3% abaixo, mínimo 30 s). Mostra a prévia antes de criar; é ponto de partida, editável.
- **Evolução do pace com testes:** em Histórico → Evolução, os testes de treino (arquivo do relógio cobrindo 5, 10, 21,1 ou 42,195 km) entram no gráfico de pace da distância junto com as provas (losango verde).
- **Dividir a carona** (Logística → Custos): combustível, pedágios, estacionamento e outros da ida e volta (sem a retirada do kit) divididos entre quem vai junto — quem é buscado na ida e quem vai junto já entram —, pessoas sem cadastro e você (opcional); WhatsApp de cada pessoa com o total, a parte dela e a chave Pix. Fica salvo na prova.
- **Stories da rotina** (`/stories`, pelo Início, “Compartilhar a semana” em Treinos, “Compartilhar este treino” num treino feito e “Story da contagem” numa prova inscrita): imagem 1080×1920 gerada no aparelho; a prévia fica no topo, os 9 modelos aparecem como miniaturas reais para deslizar e “Compartilhar”/“Baixar” ficam fixos no rodapé (no computador, prévia e opções lado a lado). Modelos — Próximas provas (até 5, inscritas primeiro), Temporada (concluídas × próximas no ano, km em provas, melhores tempos, próxima prova), Semana de treinos (dias, feitos/planejados, tempo, km, sequência), Contagem para a prova (dias, meta), Evolução nos 5 km (provas e testes), Treino concluído (em força: exercícios com séries×reps, minutos, kcal, FC média e “Nº treino da semana”), Conquista e o mês. Sem emojis: medalhas e ícones desenhados na cor do app. “Mostrar tempos e pace” e “Mostrar cidades” são opcionais; nunca vão nome, endereços nem valores. Fundo na cor do app ou com uma foto do celular (não é guardada). Compartilhar abre o menu do celular (Instagram → Story); onde não há, baixa o PNG.
- **Outras atividades** (Treinos → “+ Outra atividade”): academia/força, bike, natação, caminhada, alongamento/ioga ou outra, com duração planejada em minutos. Entram na semana de treinos (tempo, dias cumpridos, sequência e “N outras atividades”), mas não nos km de corrida, no pace, nos testes de objetivo nem nas marcas. Arquivo do relógio de bike/caminhada/natação vai para a atividade do mesmo tipo (ou vira avulsa desse tipo). Sem .FIT de treino nem envio ao Garmin.
- **Passaporte de corredora** (`/passaporte`, no Início): conquistas com a data em que vieram — primeira prova, primeiros 5/10 km, primeira meia e maratona, 5/10/25/50 provas, km em provas, cidades, treinos de corrida, treinos cruzados, semanas seguidas, metas batidas, objetivos cumpridos, Madrugadora (largada até 6h30), quarteirões no mapa e Sub X nos 5 km, 10 km e 21 km (provas e testes de treino com o arquivo do relógio). Coleção por categoria (Provas, Distâncias, Tempos, Treinos, Explorar) com “X de N conquistas”; as que faltam aparecem apagadas (só a próxima de cada família). Novas nos últimos 14 dias em destaque, “Quase lá” com barra de progresso; um toque abre os detalhes (data, como conquistar, “Postar no story”, “Ver a prova”). Aba “Recordes e números” com recordes, cidades e totais.
- **Mapa das corridas** (`/mapa`): traçados dos arquivos do relógio (.FIT, .TCX, .GPX) de treinos e provas, guardados simplificados (até 400 pontos) e **sem os primeiros e os últimos 200 m** (zona de privacidade). Km no mapa, quarteirões cobertos (~150 × 150 m) e quantos quarteirões novos cada percurso abriu. Atividades importadas antes da 0.35.0 precisam ser importadas de novo para aparecer.
- **Provas perto de você** (`/provas-perto`): provas que você fez nesta época no ano passado (buscar a edição nova ou repetir), cidades de referência (perfil e onde você corre) e buscas prontas por cidade e mês no Google e nos sites de inscrição (Ticket Sports, Corridas BR, Minhas Inscrições). Não há base aberta de calendário de provas, então o app não lista provas sozinho.
- **Ficha da academia** (Treinos → “+ Outra atividade” → Academia): exercícios com séries, repetições e carga (a sua ficha ou a do treinador; mais comuns primeiro). Com o arquivo do relógio, **planejado × feito** por exercício: “como planejado”, “parcial” ou “não feito”, carga acima do plano (+5 kg) e exercícios fora da ficha. “Repetir” cria a mesma atividade 7 dias depois, com a ficha.
- **Carga da semana** (na semana de treinos): pontos = minutos × intensidade, somando corrida, força e o resto. Intensidade pelo tempo em cada zona de FC do arquivo (Z1 = 1 … Z5 = 5), pela FC média, pelo esforço anotado ou por um peso médio por atividade; os planejados que faltam entram tracejados. Compara com a média das 4 semanas anteriores e avisa quando a semana passa 30%+ do seu normal (só com 2+ semanas de histórico). Não prescreve treino.
- **Layout mais simples:** no treino planejado, só “Enviar ao relógio” (cabo, Garmin Connect ou Intervals/Claude num painel) e “Remanejar”; no treino feito, os detalhes do relógio e “Compartilhar” primeiro. Em Treinos, Garmin e arquivo num cartão só, os 5 últimos anteriores com “Ver todos” e as opções raras (regra de treinos que passaram, importar planilha, prompt para o Claude) em “Mais opções”. No Início, Passaporte e Stories lado a lado.
- **Calendário mensal de treinos** (Treinos → aba “Mês”): semana de segunda a domingo, cada dia com o ícone de cada atividade (corrida, força, bike, natação, caminhada, alongamento) na cor da situação (feito, planejado, passou, não fiz), km ou tempo do dia e a prova inscrita marcada. Resumo do mês (feitos de planejados, tempo e km). Um toque no dia mostra o resumo de cada atividade (distância, duração, FC média, kcal, séries e exercícios), “Remanejar” e “+ Treino” no dia. No computador, arraste um treino planejado para outro dia (fica no histórico de remanejamentos).
- **Evolução na academia** (em Treinos, com os treinos de força que têm as séries do relógio): último treino de força e quantos nas últimas 4 semanas; por exercício, a carga máxima de cada treino em linha (ex.: Agachamento 40 → 50 kg), o recorde de carga e, num toque, o histórico (séries, repetições, carga, maior volume). Story do mês: força com cor própria no calendário, “X de Y treinos” e os recordes de carga do mês (com “Mostrar tempos”); atalho “Story do mês” na aba Mês. Selo “recorde” no exercício do treino que superou a carga anterior e “Força · carga máxima” na aba Recordes do Passaporte. Só mostra a evolução; não prescreve cargas.
- **Detalhes de qualquer atividade do relógio** (no treino feito, seja corrida, força, bike…): duração, distância e pace/velocidade (só quando há distância), FC média e máxima, calorias, subida, cadência, efeito do treino aeróbico/anaeróbico (Garmin, com a leitura: leve, mantém, melhora…), **séries de força** agrupadas por exercício (ex.: Agachamento · 3 séries · 12, 10, 8 reps · até 50 kg; total de repetições e volume em kg), parciais por km e o percurso no mapa. Na lista de treinos, força mostra o tempo e as kcal em vez de “0,00 km”. A importação automática do Garmin baixa o arquivo de todas as atividades; “Rever os últimos 30 dias” completa as já importadas.
- **Frequência cardíaca por zona:** ao importar a atividade (arquivo ou Garmin), o app guarda o tempo em cada faixa de 5 bpm e a FC média de cada volta; as zonas são recalculadas quando mudam. Zonas: importadas do Garmin (Perfil → Frequência cardíaca → “⌚ Importar zonas do Garmin”, `/biometric-service/heartRateZones/v2`, prefere as de corrida), digitadas, ou pelo padrão do Garmin por % da FC máxima (informada, a maior registrada em 3+ atividades, ou 220 − idade). No treino: barra e tempo por zona, FC de cada passo (♥ 130 · Z2) e a leitura (rodagem com 25%+ em Z4–Z5 → “mais forte do que uma rodagem leve costuma ser”; 70%+ em Z1–Z2 → “leve de verdade”; com tiros, só leve/moderado/forte). Na prova (arquivo do relógio) e na semana de treinos (“Intensidade da semana”, com 2+ treinos com FC). “Rever os últimos 30 dias” no Garmin completa percurso e FC dos treinos já importados.
- **Ciclo menstrual** (Perfil → Ciclo menstrual; opcional, com consentimento): registro em 2 toques (começou/terminou, fluxo, sintomas, energia), previsão pelo histórico da própria pessoa (média dos últimos 6 ciclos; “aprendendo” com 1 ciclo; faixa quando irregular), dia e fase do ciclo, cartão no Início, ponto lilás nos dias de menstruação na semana de treinos, “como você chega hoje” com o registro do dia (mesmo sem Garmin), a prova no ciclo (“cai no dia 2 da menstruação — pelo seu histórico, fluxo intenso”) com itens extras na reta final (testar absorvente/coletor no longão, banheiros no percurso, kit do ciclo, conversa com a ginecologista se for dia de fluxo intenso), sinais que merecem conversa com uma profissional (3 meses sem menstruar, ciclos fora de 21–35 dias, fluxo intenso com cansaço → ferro/ferritina, cólica forte), histórico à mão (ex.: do Flo, que não tem acesso para apps) e importação do Garmin (só leitura, tolerante a formatos). Não prescreve treino por fase; nunca aparece em stories, cards, agenda ou prompts. Sincroniza com a conta como registro `cycle` (trecho 12 do SQL); “Apagar tudo” remove do aparelho e da conta. **Fase 2 (com 3+ ciclos registrados):** “Seu ciclo e seus treinos” compara as suas rodagens (2 km+, sem tiros), a FC e a energia anotada em cada fase (menstruação, primeira e segunda metade, 5 dias antes), sempre com a amostra (“13 treinos em 4 ciclos”) e “poucos dados” abaixo de 5; e, ao remanejar um treino forte (tiros ou longo) para um dia do ciclo em que você costuma registrar energia baixa ou fluxo intenso, avisa “nos seus últimos ciclos, este dia costuma ser difícil” — aviso, não bloqueio. Especificação em `docs/backlog.md`.
- **Sincronização dos dados do Garmin:** sono, body battery, relatório e atividades vistas vão para a conta (registro `garmin`, trecho 12 do SQL) e aparecem em todos os aparelhos. A **chave pessoal não sincroniza** (credencial): em outro aparelho, cole de novo; “Desconectar” tira a chave só daquele aparelho.
- **Reta final da prova** (prova inscrita a até 28 dias; na tela da prova e no Início): linha do tempo editável — treino no ritmo da prova (~40% da distância no pace da meta, com “+ Criar este treino” no melhor dia pela regra de remanejar), testar roupa e tênis, último treino forte (avisa treino forte planejado nos 9 dias antes), semana da prova mais leve (tempo planejado × as 3 semanas anteriores, avisa acima de 85%), stories de 7 dias e de véspera, logística, kit, a noite que mais importa, separar tudo, café ~2h30 antes da largada, modo prova e resultado. O app marca sozinho o que já sabe (ritmo feito, kit no checklist, logística, resultado); o resto é marcado à mão e sincroniza (`stretchDone`). Roteiro de partida: não prescreve.
- **Avisos de treino de manhã** (Lembretes; ligados por padrão): o treino de hoje, o de ontem que ficou sem marcar (abre o treino para marcar ou remanejar) e o item do dia da reta final. Saem na rodada diária das notificações (8h de Brasília); a lógica fica em `src/lib/workoutPush.js`, usada só pelo servidor.
- **Remanejar treino** (no treino: “📅 Remanejar para outro dia”; em Treinos, no cartão “Treino que passou sem marcar”: “↷ Para qua 18/11” num toque, Outro dia, Não fiz, Fiz): o treino muda de data, volta para planejado e guarda o histórico (“remanejado · era ter 17/11”). Regra das sugestões: não no dia de outra corrida; de preferência com um dia de descanso entre corridas; nunca no dia de prova inscrita (e avisa nos 2 dias antes); de preferência na mesma semana; dentro do prazo do objetivo do plano; entre iguais, o mais cedo; treino perdido não ocupa mais o dia antigo. Regra para os que passam sem marcar (no perfil, sincroniza): perguntar (padrão), remanejar sozinho (só para dia sem avisos, até 2 vezes por treino, treinos de até 7 dias atrás) ou marcar como “não fiz”; aplicada ao abrir o app.
- **Como você chega ao treino** (com o Garmin conectado): sono (duração e nota), body battery (ao acordar ou o pico do dia) e FC de repouso do Garmin, comparados com o seu normal dos últimos 14 dias. No “Treino de hoje” (Início) e no topo de Treinos: “Boa recuperação”, “Atenção: …” ou “Sinais de cansaço: … Ouça o corpo: ir mais leve hoje é uma opção.” Em cada treino feito, “Na manhã deste treino”. Só informativo (o app não muda treinos). Dados de saúde ficam só no aparelho (60 dias), fora da conta e do backup; atualizados no máximo a cada 3 h. A função aceita as variações de formato do Garmin Connect e, se não reconhecer, mostra os nomes dos campos no cartão do Garmin.
- **Layout de computador** (a partir de 1024 px): menu lateral (Início, Corridas, Treinos, Objetivos, Histórico, Passaporte, Mapa, Stories, Provas perto, Ajustes e “Cadastrar corrida”) no lugar do menu de baixo, conteúdo até 1120 px, Início em duas colunas, stories com a prévia ao lado das opções, formulários e passaporte com largura de leitura, mapas mais altos e painéis abrindo no centro. No celular nada muda.
- **Mais stories:** “Prova concluída” (medalha com a distância, tempo ou “concluída”, pace, colocações e selos de recorde/primeira/meta; no detalhe da prova concluída, “📲 Story da prova”) e “Resumo do mês” (calendário com dias de corrida, prova e outras atividades, dias ativos, km, horas e as conquistas do mês; nos 3 primeiros dias, o mês anterior).
- **Semana que fechou:** domingo e segunda, o Início mostra “Semana fechada: 3 de 3 treinos 🔥” com atalho para o story daquela semana; com “Resumo da semana às segundas” ligado em Lembretes, a notificação de segunda também traz como foram os treinos (lidos da conta) e abre o story.
- **Importar do Garmin sozinho** (Treinos → “Importar do Garmin sozinho”): com a chave pessoal da Garmin (Garmin Connect → Configurações → Token de API pessoal; só leitura), o app busca as atividades novas ao abrir (no máximo a cada 30 min; 14 dias na primeira vez) e baixa o arquivo original: a corrida do dia marca o treino planejado como feito (voltas, parciais e percurso); academia, bike, natação etc. vão para a atividade do mesmo tipo ou viram avulsas com o nome da Garmin; se houver mais de um treino possível, pergunta. Corrida no dia de uma prova não vira treino: em Resultado da prova, “⌚ Buscar no Garmin”. A chave fica só no aparelho (fora da conta e do backup); a função `api/garmin.js` só repassa as chamadas ao servidor oficial. Só funciona no app publicado.
- **Garmin direto (sem cabo):** situação e caminhos em `docs/garmin-api.md` — envio de treinos só pela Training API (empresas, com aprovação); a API pessoal é só leitura (atividades).
- **Pessoas e lugares** (Perfil → Pessoas e lugares): quem você costuma buscar (nome; telefone e endereço opcionais) e os lugares de sempre (com tempo de parada). Na Logística, “Buscar alguém” ou “Lugar salvo” viram paradas com um toque (se a pessoa não tem endereço, o app pede e guarda). Na agenda, “Avisar quem você vai buscar” abre o WhatsApp com a mensagem e o horário calculado. Na prova, “Quem vai junto”; na retrospectiva, “Com quem correu”. Fica no perfil (rode o trecho 10 do SQL para aumentar o espaço do perfil na conta).
- **Política de privacidade** (`/privacidade`, pública): o que fica no aparelho e na nuvem, serviços externos, retenção e direitos pela LGPD. Preencha o responsável e o e-mail em `src/config.js` (`PRIVACY_CONTROLLER`, `PRIVACY_CONTACT`).
- **Convite para instalar**: no navegador, o Início mostra “Instale o PaceOn” — com botão que abre a instalação no Android/Chrome/Edge, passo a passo no iPhone/iPad (Compartilhar → Adicionar à Tela de Início) e, dentro do Instagram/WhatsApp, orientação para abrir no Safari/Chrome. Some quando o app está instalado; “Agora não” esconde por 30 dias. Sempre disponível em Ajustes → Instalar o app. Um convite por vez (instalar antes do perfil).
- **Perfil opcional** (`/perfil`, pela foto no topo do Início ou em Ajustes): nome e apelido (saudação “Boa tarde, Gi” e “Feliz aniversário”), foto (recortada e reduzida a 320 px), cidade, equipe, data de nascimento e categoria (faixa etária pela idade em 31/12, sugerida ao registrar o resultado), tamanho de camiseta (preenche o cadastro de provas), contato de emergência e tipo sanguíneo (no modo dia da prova) e nome no card de compartilhar. O cadastro continua só e-mail e senha. Sem conta, fica no aparelho; com conta, na tabela `profiles` (trecho 9 do SQL), valendo a alteração mais recente. Entra no backup.
- **Meta x realizado**: a meta de tempo é definida antes da prova direto no detalhe (com o pace e a sugestão da previsão) e, depois do resultado, comparada com o tempo feito: na chegada, na metade e em cada passagem (a cada 1, 2,5 ou 5 km, conforme a distância), com onde ganhou e onde perdeu tempo em relação ao plano. As passagens reais vêm das parciais do relógio, ajustadas à distância oficial e ao tempo líquido; sem o arquivo do relógio, compara só a chegada. Regras em `src/lib/targetCompare.js`.
- **Orçamento do ano**: um teto de gastos (objetivo do tipo orçamento) contando só inscrições ou tudo (inscrição, transporte, hospedagem e outros), com aviso ao chegar a 70–100% e ao estourar — no Início e, com as notificações ativas, no celular (uma vez por nível). Mostra o gasto (pago ou estimado), a projeção com as provas em avaliação e as provas consideradas. Atalho em Histórico → Gastos → “Definir orçamento”. Regras em `src/lib/budget.js`.
- **Decidir** (`/decidir`, atalho no Início quando há provas de interesse ou inscrição aberta): para cada prova em avaliação, custo previsto (e por km), como fica o orçamento, prazo de lote/inscrição, provas marcadas no mesmo dia ou até 3 semanas antes/depois, objetivos para os quais conta, edições anteriores já corridas e previsão de tempo. “Quanto quero” (1–3 estrelas) para ordenar, simulação de várias provas juntas (total, orçamento, provas no ano e choques de data) e ações “Me inscrevi” / “Não vou”. O mesmo resumo aparece como “Vale a pena?” no detalhe da prova. Mostra fatores; não recomenda nem prescreve treino. Regras em `src/lib/decision.js`.
- **Agenda por assinatura** e **notificações push de prazos**: em Ajustes → Agenda e avisos. Precisam de conta (ver abaixo).
- **Modo dia da prova** (`/corridas/:id/dia`): na véspera e no dia, o destaque do Início abre uma tela com contagem até a largada, número de peito grande, local com link para o mapa, aviso de kit pendente, pace e passagens da meta (ou a previsão), checklist e opção de manter a tela acesa. Funciona sem internet. Depois da largada, botão para registrar o resultado.
- **Previsão de tempo** (fórmula de Riegel, `src/lib/predict.js`): estima o tempo numa distância pelas provas concluídas dos últimos 2 anos (3 km ou mais; oficiais primeiro), priorizando distância próxima e resultados recentes e recusando extrapolar mais de 4,5×. Aparece no detalhe de provas sem meta (com “Usar como meta”), no campo de meta do cadastro e no modo dia da prova. É estimativa, não plano de treino.

## Agenda por assinatura e notificações (opcional, precisam de conta)
Rode o `supabase/schema.sql` de novo sempre que ele mudar (trechos 6 a 11; é idempotente; o trecho 6 foi atualizado para a agenda do dia na assinatura).

**Agenda por assinatura** — sem configuração extra. Cada pessoa gera um link secreto (`/agenda/<token>/minhas-corridas.ics`) e assina no iPhone, Google Agenda ou Outlook. A função `api/agenda.js` chama `calendar_feed` no banco com a chave pública; o banco devolve só nome, data, horário, local, status, nº de peito, kit e prazos (nunca custos, notas ou resultados). Trocar o link invalida o anterior. Entram as provas com data (sem canceladas/desistências) de até 1 ano atrás. Mostra o que já foi sincronizado com a nuvem. Cada calendário decide quando atualizar (o Google pode levar até um dia).

**Notificações push** — um envio por dia (Vercel Cron, `vercel.json`, 11:00 UTC = 8h de Brasília). Cada pessoa escolhe quais avisos e com quanta antecedência (vale para todos os aparelhos; trecho 8 do SQL, tabela `push_prefs`): fim da inscrição (7, 3, 1 dia ou no dia), mudança de lote (3 ou 1 dia), retirada do kit (véspera e/ou no dia, até marcar “Kit retirado”), prova (2 dias, véspera ou no dia), um resumo da semana às segundas e o aviso de orçamento. Padrão: inscrição 3 dias antes e no dia, lote na véspera, kit na véspera e no dia, prova na véspera. Sem a tabela `push_prefs`, vale o padrão. Nunca manda a mesma duas vezes (`push_log`). No iPhone, só com o app na Tela de Início (iOS 16.4+). Variáveis no Vercel (Settings → Environment Variables), depois um novo deploy:

| Variável | O quê |
|---|---|
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | Gere uma vez com `npx web-push generate-vapid-keys` |
| `VAPID_SUBJECT` | `mailto:seu-email` (contato exigido pelos serviços de push) |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Settings → API → *service_role*. **Só no Vercel**, nunca com prefixo `VITE_` |
| `CRON_SECRET` | Texto aleatório longo; o Vercel o envia ao chamar o cron |

Sem essas variáveis, o app avisa que as notificações não estão configuradas e o resto funciona normalmente. Testes: `npm test` (regras, rodada diária, funções) e `node scripts/e2e-rodada4.mjs` / `e2e-rodada5.mjs` (telas, com Supabase simulado; o push é entregue ao service worker pelo DevTools).

## Regras de custos
- Inscrição estimada = inscrição + taxas; o valor pago, quando informado, substitui a estimativa (nunca soma as duas).
- Em cada categoria (inscrição, transporte, hospedagem, outros) vale o pago; sem pago, o estimado.
- Inscrita/Concluída entram no gasto; Desisti/Cancelada só com valor pago; Interesse/Inscrição aberta aparecem como previsão.

## Logística, rotas e agenda do dia
Por prova, em abas **Ida · Volta · Kit · Custos · Agenda** (dados em `race.logistics`: sincronizam, entram no backup e funcionam sem internet).
- **Trajetos:** saída (casa), até 8 paradas com tempo de permanência (reordenáveis), destino = local da prova do cadastro. Volta com as mesmas paradas ao contrário ou outras, e horário de saída. Kit em trajeto separado (pode ser em outro dia; ida e volta opcional). Endereços favoritos ficam no perfil.
- **Rota:** distância e tempo por trecho e no total, mapa (Leaflet + OpenStreetMap, carregado só nesta tela) e links para Google Maps (com paradas) e Waze (um trecho por vez, limitação do Waze). Mudou um endereço → a rota aparece como desatualizada.
- **Custos:** veículo no perfil (km/l, combustível, R$/litro). Combustível = distância ÷ consumo × preço por litro, por sentido e para o kit; pedágios por sentido (da rota quando o serviço informa a tarifa, senão à mão); estacionamento e outras despesas; estimado e pago por item. O total vira o **Transporte** da prova (`transportEst`/`transportPaid`), então orçamento, Gastos e Decidir já enxergam — sem duplicar. Enquanto houver item sem valor pago, o total fica como estimado.
- **Agenda (Gerar minha agenda):** de trás para frente a partir da largada: chegada desejada, estacionar, trajeto (com trânsito previsto quando houver) + paradas, margem para imprevistos → **sair de casa**; preparativos finais, vestir, café (opcional), banho → **acordar**; depois aquecimento, posicionamento e largada. Recalcula sozinha. Os tempos podem virar padrão do perfil. Para rotas sem trânsito previsto (OpenRouteService ou à mão), há o “Acréscimo por trânsito (%)”, aplicado só a esses trechos. Com a volta planejada, o horário de saída do local também vai para o .ics. Regras em `src/lib/schedule.js` e `src/lib/logistics.js`.
- **Modo dia da prova:** próxima atividade, hora de sair, agenda, paradas, rota e chegada prevista.
- **Calendário e avisos:** “Baixar agenda com alarmes (.ics)” cria eventos “Acordar”, “Sair de casa” e “Sair para o kit” com alarme no calendário do celular (o jeito confiável de acordar: o app não é despertador). Opcionalmente os horários vão para a agenda por assinatura, sem endereços (rode de novo o trecho 6 do SQL). A notificação da véspera inclui “acordar” e “sair”.

**Busca de endereços (sem chave):** `api/_geocode.js` combina **CEP** (BrasilAPI, com ViaCEP de reserva), **Photon** e **Nominatim** (OpenStreetMap), além do Google/OpenRouteService quando configurados; junta, tira repetidos e ordena pelo que mais combina com o texto. Sugestões aparecem enquanto você digita (Photon), “📍 Usar minha localização” preenche a saída, e dá para usar o endereço como digitado. Funciona mesmo sem chave de rotas (o mapa já aparece com os pontos verificados).

**Serviço de rotas (opcional)** — função `api/route.js`; a chave fica só no servidor (Vercel → Environment Variables, sem `VITE_`):

| Variável | Serviço | Trânsito previsto | Pedágios | Custo |
|---|---|---|---|---|
| `GOOGLE_MAPS_API_KEY` | Google Routes API + Geocoding API | sim (saída futura) | quando o Google tem a tarifa | precisa de conta de faturamento; cota mensal gratuita (confira a tabela atual) |
| `ORS_API_KEY` | OpenRouteService | não | não | gratuito (limite diário) |
| nenhuma | — | — | — | distância e tempo informados à mão |

No Google Cloud: ative **Routes API** e **Geocoding API**, restrinja a chave a essas duas APIs e defina cotas diárias (protege contra uso indevido). A função aceita só chamadas do próprio site e limita consultas por IP. O mapa usa os mapas do OpenStreetMap (uso leve, com atribuição).

## Fora do escopo
GPS, prescrição de treinos (o app guarda e exporta os treinos que você monta, mas não cria treinos), rede social, integração por conta com Garmin/Strava (por enquanto, a troca é por arquivo), busca automática de provas. O card de compartilhar gera só a imagem; não publica em nenhuma rede.
